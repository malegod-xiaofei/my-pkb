第一步写的是一份很薄的 `AGENTS.md`。规则正文放在 `docs/`，Cursor 规则只在改到对应目录时把人拉回那份文档。这个仓库就是这么拴住人和 AI 的。

## 先定地图，再写入口

`AGENTS.md` 是索引，不是规格。规格在 `docs/`，一份文档只回答一类问题。入口文件每次对话都会进上下文，写长了后面的细则反而没人看。

照这个仓库，起步只要这几样：

AGENTS.md # 一页索引：先读什么、最容易踩的几条、本地命令

docs/README.md # 路由表：带着什么问题读哪一份

docs/glossary.md # 术语。新概念先在这里定义

.cursor/rules/00-….mdc # 每次都加载：文档是权威，链回路由表

README.md # 人的入口，第一段指向 AGENTS.md 和 docs/README.md

领域文档（状态机、接口、表、部署）先空着，做到哪一块再补哪一份。路由表里先写上名字和「这份回答什么」，避免两处各写一套。

## AGENTS.md 只放四块

对照本仓库的 `AGENTS.md`，每块都短：

1. 先读什么。 第一行指向 `docs/README.md`，第二行指向术语表。后面按问题列链接：改状态机读哪份、改接口读哪份、改表读哪份。写「按落点读那一份，不必通读」。
2. 最容易踩的几条。 本仓库是六条，每条一句话，末尾链到细则所在的文档。这里只留违反了会写错代码的那几条。
3. 本地命令。 测试、检查、启动各一条，外加「全绿还说明不了什么」（这个仓库是：SQLite 全绿不等于能在 MySQL 上跑）。
4. 规则怎么加载。 点名 `.cursor/rules/` 里哪条规则绑哪个目录。

细则、字段表、错误码都不要抄进来。改行为时只改 `docs/` 那一处，入口不用跟着改。

## 然后配 Cursor 规则

规则是钩子，正文仍在文档里。本仓库 `.cursor/rules/` 的分法可以直接照：

|文件|何时进上下文|里面写什么|
|---|---|---|
|`00-docs-authority.mdc`|`alwaysApply: true`，每次都在|「改行为先改文档，再改代码」+ 路由表缩影 + 术语从哪份来|
|`10-layering.mdc`|`globs: app/**`|分层边界，链到模块文档|
|`20-api-contract.mdc`|`globs: app/api/**, app/schemas/**`|契约里最容易写错的几条，链到 `docs/api/`|
|`30-data-migrations.mdc`|`globs: app/models/**, alembic/**`|表和迁移的坑，链到数据模型文档|
|`40-tests.mdc`|`globs: tests/**`|怎么跑、断言以哪份文档为准|
|`50-deploy-config.mdc`|`globs: deploy/**, .env*`|配置和发布里不能改错的几条|

每条规则开头用 YAML 写 `description` 和 `globs`（或 `alwaysApply`）。正文控制在「打开这类文件时最容易写错的几条」，每条链回 `docs/` 的章节。规则里再抄一遍接口表，文档一改规则就过时。

`alwaysApply` 只留那一条权威规则。其余都用 `globs`，改到 API 才看见契约，改到测试才看见测试约定。

## 术语表是第二份正文

`docs/glossary.md` 比状态机、接口更早写。后面所有文档和规则都用这里的词。本仓库的做法是：一个概念只在这里定义；中文动作词列一张允许表；禁止的别名列一张对照（「上架」不写成「发布」）。新功能先在术语表落一个词，再写那份领域文档，再改代码。

## 做到哪一块，补哪份文档

路由表先占位，内容按改动补。这个仓库的切法是按问题，不按目录：

- 一个东西从创建到结束怎么走 → 生命周期
- 谁能看见什么 → 读路径
- 一次写入的顺序和事务 → 写路径
- 模块各自干什么 → 模块
- 一个接口的路径、请求、错误码 → `docs/api/`，共性一份、每个面一份
- 表和约束 → 数据模型
- 怎么发布 → 部署与配置
- 目录、本地命令、已知欠账 → 工程约定（本仓库的 `dev-plan.md`）

每份文档开头写「本文不写什么」。状态机只在生命周期那份，事务步骤只在写路径那份，别处需要时给链接。

工程约定里留一张欠账表，仓库外或还没自动做的事集中记在那里，不散落到各份文档。

## 用一条测试把文档钉住

本仓库的 `tests/test_doc_refs.py` 检查文档之间的章节引用和链接，改了章节号或挪了文件，测试会红。规则里写明：覆盖新行为之前，文档里已经有这段描述；断言对的是文档里的规则，不是某次实现的内部细节。

本地命令写进 `AGENTS.md` 和工程约定，两边同一条。这个仓库是 `pytest -q` 加 `ruff check` / `ruff format --check`，启动是 `python -m app.main`。

## 可以后做的

领域代码、Dockerfile、流水线都排在上面这套之后。镜像和 k8s 清单要有的话，再补部署文档和 `50-deploy-config` 那条规则。流水线本身不必写进 `AGENTS.md`，发布顺序放在部署文档里，规则只留「探针别改错、配置只在启动时读一次」这种坑。
